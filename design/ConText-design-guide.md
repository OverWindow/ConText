# ConText — Crimson / Warm White / Charcoal 디자인 가이드

따뜻한 흰 배경과 흰 표면 위에 크림슨과 와인색을 배치하고, 본문은 차콜로 표시한다. 문서와 캔버스가 중심이며 색은 동작, 선택, AI 근거의 위치를 안내한다.

## 파일

- `../packages/workspace-ui/assets/tokens.css`: 웹·데스크톱의 공통 색상 원본. `frontend/design/tokens.css`를 통해 웹에서도 import한다.
- `ConText-palette.png`: 공유용 색상표 이미지. HTML에서 렌더링한 정적인 스냅샷이므로 토큰 변경 후 다시 렌더링한다.
- `ConText-palette.html`: 브라우저로 열어 보는 색상표와 컴포넌트 샘플. 위 CSS를 직접 참조한다. 폴더 구조를 유지하여 함께 전달한다.
- `../frontend/app/globals.css`: 컴포넌트별 적용과 기존 레이아웃.
- `../frontend/features/canvas/document-card.tsx`, `document-card.css`: 캔버스의 접힌 종이형 파일 카드와 전용 스타일.
- `ConText-canvas-files.png`: 파일 형식 5종을 확인하는 데스크톱 테스트 화면.

## 기본 팔레트

로고는 Crimson **#A40F16**, Wine **#7C334B**, Charcoal **#2A2526**, Muted Rose **#C89C9D**를 사용한다. `Con`과 T는 차콜, `Text`와 C는 크림슨이다. [브랜드 파일 안내](brand/README.md)에 원본·내보내기·편집 프롬프트를 기록했다.

| 역할 | 값 | CSS 변수 | 적용 |
|---|---|---|---|
| Primary | `#A40F16` | `--primary` | 선택 표시, 연결선, 포커스 |
| Secondary | `#7C334B` | `--secondary` | AI 그라데이션, AI 보조 강조 |
| Background | `#FAF8F5` | `--background` | 페이지와 캔버스 |
| Surface | `#FFFFFF` | `--surface` | 메뉴, 카드, 입력창 |
| Text | `#2A2526` | `--text` | 제목과 본문 |
| Border | `#E8DEDD` | `--border` | 패널, 카드, 입력창 테두리 |

## 변형 색과 사용 규칙

- 주요 버튼: `--primary-strong` **#A40F16**, hover **#850C12**, 흰 글자. 작은 글자의 흰색 대비도 확보하며, 호버는 같은 색상 계열에서 한 단계 어둡게 표시한다.
- 선택된 메뉴·사용자 질문: `--primary-soft` **#F8E9E9**. 선택된 메뉴는 크림슨 안쪽 선을 함께 표시한다.
- AI 응답: `--surface-ai` **#FCF5F6**. 인용 버튼은 **#F7EDF0** 바탕과 **#7C334B** 글자로 표시한다.
- 보조 본문: **#574D50**, 설명·메타데이터: **#6E6365**. 따뜻한 회색 계열로 본문 위계를 구분한다.
- 선택 테두리: **#D8A6A8**, AI 인용 테두리: **#DEC0CB**. 일반 구획선은 기본 Border를 사용한다.
- 격자: `--grid` **#EAE3E0**, 간격 28px. 콘텐츠보다 격자가 먼저 보이지 않게 유지한다.
- 채팅 헤더에 크림슨→와인 그라데이션을 제한적으로 사용한다. 로고는 제공된 이미지 자체의 색을 사용하며 일반 버튼과 카드 표면은 단색이다.
- 그림자는 Text 계열의 낮은 불투명도를 사용한다. 레이아웃이나 크기를 바꾸지 않고 색으로 표면의 깊이를 표현한다.

## 상태와 파일 형식

상태와 파일 형식은 브랜드 색과 구분되는 보조 팔레트를 쓴다. 색만으로 의미를 전달하지 않고 텍스트·아이콘을 함께 표시한다. 아래 표는 공통 상태 및 문서 목록/미리보기 기준이며, 캔버스 파일 카드는 다음 절의 전용 팔레트를 사용한다.

| 용도 | 글자/선 | 배경 |
|---|---|---|
| 성공·READY·HWPX | `#226B58` | `#EDF6F0` |
| 경고·TXT | `#8A5B20` | `#FCF4E5` |
| 오류·삭제 | `#AD3C2F` | `#FFF0EA` |
| 정보·DOCX | `#4E6471` | `#EFF3F4` |
| Markdown·AI 인용 | `#7C334B` | `#F7EDF0` |

Diff 추가·삭제 및 인용 원문 강조는 각 의미에 맞는 녹색·빨강·노랑을 유지한다. 캔버스 도형은 와인/크림슨/초록/노랑/분홍/회색으로 표시한다. 기존 저장 키 `violet`/`blue`는 호환성을 위해 유지하고, 화면 이름만 와인/크림슨으로 표시한다.

## 캔버스 파일 카드

참고 이미지의 접힌 종이 실루엣, 중앙의 큰 형식 아이콘, 분리된 제목 라벨을 반영한다. SVG와 CSS로 그려 확대해도 선명하게 유지한다.

- 종이 영역은 캔버스 좌표 기준 200×244px이다. 우측 상단 접힘은 약 49px이며, 얇은 테두리와 낮은 그림자를 사용한다.
- PDF는 문서 아이콘, DOCX는 W, HWPX는 한, Markdown은 M↓, TXT는 가로줄로 구분한다.
- 아래쪽에는 현재 버전의 파일 크기와 버전 번호, 처리 상태를 표시한다. 여러 버전이 있으면 전체 개수를 함께 표시한다.
- 상태 점은 실제 처리 상태를 나타낸다. 연결이 있으면 실제 연결 개수를 작은 링크 배지로 표시한다.
- 확장자가 포함된 원본 파일명만 종이 아래 라벨에 최대 두 줄로 표시한다. 긴 내용은 말줄임과 툴팁을 사용한다.
- 선택 시 Primary 외곽선과 제목 라벨 배경을 함께 강조한다. 편집 모드의 연결 핸들은 종이의 상하좌우 중앙에 둔다. 네 방향 모두 시작점과 도착점으로 쓸 수 있으며, 선택한 방향은 관계와 함께 저장한다. 기존 연결은 오른쪽에서 왼쪽으로 유지하고, 같은 관계를 다른 방향으로 다시 연결하면 위치를 갱신한다.
- 새 문서는 기본 행 간격 370px로 배치한다. 사용자가 저장한 위치는 유지한다.

| 형식 | 아이콘·접힘 색 | 아이콘 배경 | 종이 테두리 |
|---|---|---|---|
| PDF | `#C56065` | `#FBEDEE` | `#E9C8CB` |
| DOCX | `#7C6D70` | `#F3EFEC` | `#DED5D2` |
| HWPX | `#36827C` | `#EEF7F4` | `#CCE2DC` |
| Markdown | `#9C5B70` | `#F7EDF0` | `#E5CDD6` |
| TXT | `#8C8076` | `#F4F0EB` | `#E4DBD2` |

전용 색의 원본은 공통 토큰의 `--file-*`이며 `packages/workspace-ui/shared/ui/document-paper.css`의 `--paper-accent`, `--paper-soft`, `--paper-border`에서 관리한다. 표면·본문·선택·상태 색은 공통 토큰을 사용한다.

파일 아래 이름은 확장자가 포함된 원본 파일명 하나만 표시한다. 별도의 문서 제목과 작은 보조 파일명은 중복 표시하지 않는다.

### 호버 형식 변환 패널과 결과 아이콘

- 파일에 호버하면 오른쪽 14px 간격에 지름 48px의 원형 변환 버튼과 오른쪽의 ‘형식 변환’ 라벨이 나타난다. 버튼을 누르면 같은 위치에서 240px 폭의 변환 카드로 확장된다. 마우스를 올리거나 키보드로 포커스하는 것만으로 카드를 열지 않는다. 터치 환경에서는 원형 버튼을 항상 표시한다.
- 패널에서 원본 버전을 고른 뒤 PDF, DOCX, TXT, Markdown으로 변환한다. 처리 중인 원본은 변환 버튼을 비활성화하고 이유를 표시한다.
- 원형 버튼을 클릭하면 패널을 열어 둔다. 닫기 버튼, Escape, 바깥 클릭으로 닫을 수 있고, 닫기 버튼과 Escape는 원형 버튼으로 키보드 포커스를 돌려준다. 문서를 드래그하거나 연결선을 조작할 때에는 패널을 숨긴다.
- 대기·진행·실패·완료 상태를 실제 변환 API와 연동한다. 실패한 형식은 다시 시도할 수 있고 완료된 형식은 다운로드 동작으로 바뀐다.
- 평소에는 파일 왼쪽의 작은 배지로 `PDF · DOCX / 변환됨`을 안내한다. 파일에 호버하거나 키보드로 포커스하면 왼쪽에 완료된 파일 아이콘과 원본 수정 이력 번호·왼쪽 방향 점선 화살표를 표시한다. 아이콘을 누르면 해당 수정 이력의 변환 파일을 다운로드한다. 모바일은 완료 배지를 탭해 펼치고 바깥을 탭해 접는다.
- 결과 목록이 길어지면 독립적으로 스크롤한다. 원본과 함께 움직이며 별도 위치 저장이나 문서 관계를 추가하지 않는다. 새로고침 후에도 저장된 변환 이력으로 복원한다.
- 캔버스 변환 패널 하단의 상시 설명 문구는 생략한다. 진행 상태와 오류·개별 변환 경고만 필요한 경우 표시한다.
- 변환은 본문·제목·목록·표 중심이며 원본 이미지와 복잡한 배치는 포함하지 않는다. 원본 문서의 현재 버전은 바뀌지 않는다.

구현: `frontend/features/canvas/document-conversions.tsx`, `document-conversions.css`. 공통 변환 타입과 다운로드 처리는 `frontend/features/documents/conversion-api.ts`에 있다. 캔버스 조회 응답은 워크스페이스에 속한 모든 버전의 변환 요약을 함께 반환하고, 대기·진행 작업이 있으면 5초 간격으로 갱신한다.

화면 예시: [호버 원형 버튼](ConText-canvas-conversion-launcher.png), [확장된 변환 카드](ConText-canvas-conversion-panel.png), [변환 결과와 버전 화살표](ConText-canvas-conversion-results.png).

## 컴포넌트와 레이아웃

- 왼쪽 메뉴는 펼침/아이콘 압축 모드를 유지한다. 모바일 기본은 압축이다.
- 오른쪽 AI 채팅은 비모달 패널이다. 접었다 펼쳐도 초안과 대화가 유지된다.
- Primary 버튼은 한 영역에서 가장 중요한 동작에 사용한다. 보조 버튼은 흰 표면과 Border, AI 근거 링크는 와인색을 사용한다.
- 포커스는 Primary 외곽선으로 드러낸다. hover·선택·비활성 상태를 구분한다.
- 기존 둥근 모서리와 간격을 유지한다: 입력/버튼 8–12px, 카드 14–15px, 메뉴/패널 18–20px.
- 새 컴포넌트에서는 임의의 HEX를 추가하기 전에 `tokens.css`의 역할별 변수를 사용한다.

```css
.example-action {
  background: var(--primary-strong);
  color: var(--on-primary);
  border: 1px solid var(--primary-strong);
}
.example-source {
  background: var(--secondary-soft);
  color: var(--secondary-strong);
  border: 1px solid var(--secondary-border);
}
```

이 가이드는 현재 밝은 테마 기준이다. 다크 테마는 아직 정의하지 않았다.

## AI 검색·답변의 캔버스 참조 표시

- 검색 결과나 완료된 AI 답변을 표시하면 첫 참조 문서를 사용 가능한 캔버스 중앙으로 부드럽게 이동한다. 왼쪽 메뉴와 오른쪽 채팅 영역은 중앙 계산에서 제외한다. 문서의 저장된 위치와 현재 버전은 바꾸지 않는다.
- 참조된 모든 문서에 크림슨 외곽선과 `AI 참조 · V1` 배지를 표시한다. 여러 버전을 인용하면 버전 번호를 함께 표시해 현재 파일 버전과 구분한다.
- 새 결과와 출처 클릭 시 1.5초 간격으로 3회 은은하게 빛난 뒤 정적인 강조를 유지한다. 주기적인 대화 갱신으로 화면 이동이나 애니메이션을 반복하지 않는다.
- 답변의 인용 번호 또는 검색 결과의 출처 제목을 누르면 해당 파일로 다시 이동하고 강조한다. 기존 ‘인용한 버전 열기’는 원문 미리보기를 유지한다.
- 새 대화·빈 검색 결과·채팅 닫기 시 강조를 해제한다. 캔버스 제목 필터가 참조 문서를 가리지 않도록 결과 표시 시 필터를 비운다.
- 모바일에서는 참조 문서가 있을 때 상단 30%에 캔버스, 하단 70%에 대화를 표시한다. 동작 줄이기 설정에서는 이동과 맥동을 생략하고 정적인 테두리·배지만 표시한다.

구현: `frontend/features/chat/chat-panel.tsx`, `frontend/features/canvas/workspace-canvas.tsx`, `frontend/features/canvas/document-card.tsx`, `document-card.css`.

검증 화면: [데스크톱 AI 참조](ConText-canvas-ai-reference.png), [모바일 AI 참조](ConText-canvas-ai-reference-mobile.png). 테스트용 문서와 답변으로 촬영한 예시다.


## 복사본 생성과 수정 이력 용어

- 파일 호버 메뉴의 ‘형식 변환’ 아래에 같은 크기의 ‘복사본 생성하기’ 버튼을 배치한다. 편집 권한이 있는 사용자에게 표시하고, 업로드 중인 파일은 비활성화한다.
- 현재 수정 이력의 원본 파일과 본문으로 새 문서를 생성한다. 이름은 확장자 앞에 ` copy`를 붙이며 중복이면 ` copy 2`, ` copy 3` 순서로 구분한다. 과거 수정 이력이나 문서 관계를 복제하지 않는다.
- 복사본은 새로운 문서와 첫 수정 이력을 가지며 원본 옆의 빈 위치에 저장한다. 생성 후 복사본으로 화면을 이동하며 새로고침 후에도 문서와 배치가 유지된다.
- 서버가 반복 요청을 같은 결과로 처리하고, 생성 중에는 버튼을 잠근다. 처리 완료된 본문은 즉시 사용할 수 있고 처리 전 원본은 복사본에 별도의 본문 처리 작업을 등록한다.
- 파일 내부의 ‘버전’ 표기는 ‘수정 이력’으로 통일한다. 메뉴는 ‘수정 이력’, ‘새 수정 이력’, ‘수정 이력 비교’로 표시하고 작은 배지는 ‘이력 1’ 형태로 표시한다. 데이터 구조와 API의 내부 이름은 유지한다.

저장소의 검증된 원본과 처리 결과는 변경 불가능한 객체이므로 공유하되, 복사본 문서·수정 이력·처리 상태·캔버스 위치는 독립 레코드로 관리한다. 이후 새 수정 이력 추가와 현재 이력 지정은 각각의 문서에만 적용된다.

호버 유지: 파일과 오른쪽 동작 사이 및 두 버튼 사이의 빈 공간을 투명한 연결 영역으로 포함한다. 위아래 16px 정도의 여유와 320ms 닫힘 지연을 두며, 버튼이나 결과 목록으로 다시 진입하면 닫힘을 취소한다.

## 캔버스 되돌리기·다시 실행

- 상단 수정 버튼 옆에 왼쪽 굽은 화살표 ‘되돌리기’, 오른쪽 굽은 화살표 ‘다시 실행’을 한 묶음으로 표시한다. 되돌릴 작업이 없거나 저장·복원 중이면 비활성화한다. 읽기 전용 사용자에게는 표시하지 않는다.
- 파일 이동, 연결 추가·삭제, 연결 방향 변경을 최근 50개까지 기록한다. 한 번의 드래그는 한 작업으로 취급하고 복원한 위치·연결도 서버에 저장한다.
- 새 작업을 하면 다시 실행 목록을 비운다. 기록은 현재 화면에서만 유지하며 새로고침하면 초기화된다. 파일 본문·수정 이력·복사본·형식 변환·텍스트와 도형 편집은 이 기록에 포함하지 않는다.
- 캔버스에 초점이 있을 때 Ctrl/⌘+Z는 되돌리기, Ctrl/⌘+Shift+Z와 Ctrl+Y는 다시 실행이다. 입력창·대화·문서 편집에서는 기존 텍스트 편집 단축키를 유지한다.
- 저장 실패 시 작업을 기록에 남겨 재시도할 수 있게 안내한다. 모바일에서는 검색을 별도 줄에 배치해 버튼이 화면 밖으로 밀리지 않게 한다.

검증 화면: [데스크톱 되돌리기](ConText-canvas-undo-desktop.png), [모바일 되돌리기](ConText-canvas-undo-mobile.png). 테스트 문서로 촬영한 예시다.

## 수정 모드의 화면 테두리

- 수정 모드에만 화면 가장자리에서 2px 안쪽으로 얇은 크림슨 테두리와 은은한 안쪽 빛 효과를 표시한다. 둘러보기 모드에서는 숨긴다.
- 0.2초 페이드 전환만 사용하고 반복 맥동은 하지 않는다. 동작 줄이기 설정에서는 즉시 전환한다.
- 효과는 클릭·드래그·터치를 가로채지 않는다. 되돌리기 저장 중에도 수정 모드 표시를 유지한다.

## 사각형 폴더와 확대·축소 표시

- 기존 사각형 배경을 캔버스 폴더로 사용한다. 수정 모드의 폴더 아이콘으로 추가하고, 사각형 하단 **안쪽**의 이름 또는 편집 패널에서 이름을 입력한다. 기존 사각형도 이름을 붙일 수 있다.
- 파일 카드 전체가 사각형 안에 들어오면 자동으로 포함된다. 겹치는 폴더에서는 가장 작은 영역을 우선하며 같은 크기는 고정된 ID 순서로 정한다. 사각형 크기나 파일 위치가 바뀌면 포함 여부를 다시 계산한다.
- 수정 모드에서 파일 중심을 폴더 안이나 테두리 바깥 40px 이내(캔버스 좌표)에 놓으면, 파일이 밖으로 걸쳐 있어도 대상 폴더를 자동 확장한다. 파일 주변 48px와 하단 이름 영역 80px를 확보하고 기존 파일 위치는 유지한다. 외부 파일과 다른 폴더의 파일 모두 지원한다. 드래그 중에는 대상 폴더 확장과 원래 폴더 축소를 점선 테두리로 미리 보여주며 저장하지 않는다. 원래 자리로 돌아오면 미리보기도 복원된다. 크기·위치와 이름 표시는 0.24초의 감속 전환으로 부드럽게 연결한다. 폴더를 직접 끌거나 크기를 조절할 때는 지연을 없애고, 동작 줄이기 설정에서는 전환을 끈다. 파일을 놓으면 양쪽 크기를 저장한다. 원래 폴더는 남은 파일과 여백에 맞춰 줄이고, 빈 폴더는 최소 320×240px(기존 영역이 더 작으면 기존 크기)로 유지한다. 되돌리기·다시 실행은 파일 위치와 자동 확장·축소된 폴더 영역을 함께 복원한다. 최대 크기 2000px를 넘는 경우 안쪽으로 더 옮기도록 안내한다.
- 평소 이름은 하단에서 10px 안쪽에 배치한다. 흰 배경·테두리·그림자 없이 옅은 12px 글자와 작은 아이콘으로 표시한다. 폭은 배경 안으로 제한하고 긴 이름은 말줄임한다. 작은 폴더에서는 장식 아이콘과 개수보다 이름을 우선한다. 축소 시 중앙 이름은 별도로 선명하게 유지한다.
- 보기 모드에서 배율이 38% 미만이면 포함된 파일 대신 **배경 중앙**에 폴더 아이콘·이름·파일 개수를 표시한다. 매우 작은 영역에서는 이름을 우선한다. 폴더 표시를 누르면 확대하며, 직접 확대해도 개별 파일이 복원된다.
- 축소 표시 중 내부 파일에 붙은 연결선은 함께 숨겨 끝점만 남는 선을 방지한다. 파일과 연결 데이터는 그대로 유지된다. 폴더 밖 문서는 계속 표시한다.
- 수정·영역 선택·검색·AI 참조 확인 중에는 파일을 펼친다. 폴더 이름 검색으로 그 안의 문서들을 찾을 수 있다. 읽기 전용 사용자도 폴더 펼치기와 검색이 가능하다.
- 이름은 기존 사각형의 text 필드에 저장하고, 포함 관계는 저장된 영역과 파일 위치에서 계산한다. 폴더 삭제는 배경만 제거하며 파일은 보존한다.

자동 확장·축소와 여백 확인: [데스크톱 파일 이동](ConText-folder-transfer-desktop.png), [모바일 파일 이동](ConText-folder-transfer-mobile.png).

검증 화면: [축소한 폴더](ConText-folder-overview-desktop.png), [모바일 축소](ConText-folder-overview-mobile.png), [확대한 폴더](ConText-folder-detail-desktop.png), [모바일 확대](ConText-folder-detail-mobile.png). 테스트용 문서와 폴더로 촬영했다.

## 영역 선택과 요약 파일

- 하단 확대·축소·전체 보기 도구 칸의 영역 선택 아이콘(점선 사각형과 커서)을 누르면 빈 공간과 파일 위에서 드래그해 사각형을 그릴 수 있다. 마우스와 터치를 지원하며, 파일 카드 전체가 영역 안에 들어온 문서만 선택한다. 검색으로 숨긴 문서와 텍스트·도형은 제외한다. 선택 중에도 파일 아이콘과 파일명은 유지하며, 형식 변환·복사본 등 옆 메뉴만 숨긴다.
- 선택 모드에서는 파일 이동·미리보기·변환 메뉴 대신 선택에 집중한다. 선택한 파일에는 크림슨 테두리를 표시한다. 확대·축소는 계속 가능하며 Escape 또는 닫기 버튼으로 선택을 해제한다.
- 선택 후 아래 작업 카드에 개수와 파일명을 표시하고 ‘요약 파일 만들기’를 제공한다. 현재 수정 이력의 본문이 준비된 파일 1–8개를 지원한다. 생성 중에는 중복 클릭을 막고 실패 시 같은 요청으로 재시도한다.
- 성공하면 독립된 Markdown 문서를 선택 영역 오른쪽에 배치하고 화면을 이동한다. 첫 수정 이력과 본문·다운로드가 즉시 준비되며, 각 원본 문서로 ‘생성 출처’ 연결을 저장한다. 이름 중복은 번호로 구분한다.
- 요약 파일에는 AI 생성 표시, 인용 출처, 요약에 사용한 문서·수정 이력 식별 정보를 보존한다. 모든 선택 문서의 근거가 포함되지 않으면 빈 파일을 만들지 않고 재시도를 안내한다.
- 한 요청에서 원문은 총 24,000자 이내로 나누어 사용한다. 긴 문서는 앞부분을 사용하며 이 경우 요약 파일에 범위를 명시한다. 워크스페이스에 속한 문서만 허용하고 생성에는 편집 권한이 필요하다.

검증 화면: [영역 선택](ConText-area-selection-desktop.png), [모바일 영역 선택](ConText-area-selection-mobile.png), [요약 파일](ConText-summary-file-desktop.png), [모바일 요약 파일](ConText-summary-file-mobile.png). 테스트 문서와 요약으로 촬영한 예시다.
