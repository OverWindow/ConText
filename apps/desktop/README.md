# ConText Desktop

웹과 주 메뉴, 문서 카드, 캔버스 도구, 미리보기, 수정 이력·비교·후보, 블록 편집기, ChatKHU 설정과 채팅 UI를 공유하는 로컬 작업 공간입니다. 폴더·파일·초안·검색은 로그인과 인터넷 없이 사용할 수 있습니다. AI 요청은 별도로 연결합니다.

## 실행

이 체크아웃에는 빌드된 독립 파서가 준비되어 있습니다. 저장소 루트에서 실행합니다.

```bash
cd apps/desktop
npm run dev
```

Node.js 24 이상을 사용합니다. `dev`는 UI를 빌드한 뒤 Electron을 실행합니다. 이미 빌드했다면 `npm start`로 실행합니다. 개발 중 변경은 종료 후 다시 실행하면 반영됩니다.

새 환경에서 소스부터 준비할 때는 저장소 전체와 양쪽 프런트 의존성이 필요합니다.

```bash
npm ci --prefix frontend
npm ci --prefix apps/desktop
python3.12 -m venv apps/desktop/processor/.venv
apps/desktop/processor/.venv/bin/python -m pip install -r apps/desktop/processor/requirements.lock
npm run processor:build --prefix apps/desktop
npm run dev --prefix apps/desktop
```

빌드에는 Python 3.12 이상을 사용합니다. Windows의 가상 환경 Python 경로는 `processor/.venv/Scripts/python.exe`입니다. 다른 Python 환경을 쓰면 `CONTEXT_PROCESSOR_PYTHON`으로 빌드용 실행 파일을 지정합니다. 설치된 앱은 포함된 파서를 실행하므로 사용자 PC에 Python·Docker를 설치할 필요가 없습니다. 나눔고딕과 라이선스는 `processor/assets`에 포함합니다.

## 기본 사용

1. **폴더 연결**로 작업 공간을 만듭니다. 하위 폴더는 웹과 같은 캔버스 영역으로 표시됩니다. 멀리 축소하면 영역 이름과 항목 수가 보이고, 보기 모드에서 확대하거나 폴더 대표 카드를 누르면 같은 캔버스 안에서 파일과 중첩 폴더가 드러납니다. 상단의 큰 작업 공간 제목을 누르면 루트 전체 보기로 돌아옵니다. 작은 경로 행·뒤로 화살표·우측 파일 수는 표시하지 않습니다. 별도의 **안으로** 버튼은 표시하지 않습니다.
2. 폴더 영역은 작은 간격의 여러 행으로 자동 배치합니다. 폴더 이름은 줄바꿈해 끝까지 표시합니다. 같은 폴더 안에 파일과 하위 폴더가 섞이면 파일 카드를 폴더 대표 카드와 같은 크기로 자동 확대합니다. 파일만 있는 폴더는 기본 크기를 사용합니다. 직속 파일과 하위 폴더의 합계가 8개부터 영역은 1093×793 캔버스 좌표로 고정되고, 내부 항목과 간격을 비례 축소해 담습니다. 중첩 폴더에도 적용하며 저장된 원래 좌표는 유지합니다. 이미 직접 옮긴 영역은 유지합니다. 흩어진 영역은 상단 **모아 정렬**로 현재 폴더 안의 표시된 영역을 모을 수 있고, **되돌리기**로 원래 배치에 돌아갑니다. **캔버스 수정**에서 파일 배치, 텍스트·사각형 폴더·타원·삼각형, 문서 연결을 편집합니다. 연결선 선택 시 삭제 옵션이 나옵니다. 파일 이동·연결은 되돌리기/다시 실행과 Ctrl/⌘+Z를 지원합니다. 편집 전후 폴더 박스의 크기·배치·화면 배율·펼침 상태를 유지합니다. 확대해서 보이던 내부 파일은 수정 모드에서도 그대로 끌어 옮깁니다. 별도 이동 손잡이 없이 박스 배경이나 대표 카드 자체를 끌어 이동합니다. 접힌 폴더는 보기 모드에서 대표 카드를 누르거나, 수정 모드에서 두 번 눌러 펼칩니다. 영역 이동이나 논리 폴더·도형 조작은 원본 디스크 경로를 유지합니다. 실제 파일을 다른 물리 폴더 위에 놓으면 디스크에서도 그 폴더로 이동하며, 되돌리기/다시 실행을 지원합니다. 같은 이름의 대상 파일이 있으면 양쪽 파일을 보존하고 이동을 거부합니다. 여러 파일을 함께 옮기면 완료된 파일마다 개별적으로 되돌릴 수 있습니다. 마지막 작업 폴더와 편집 모드는 재시작 후 복원합니다.
3. 파일을 선택해 공통 미리보기·수정 이력·비교·내보내기를 사용합니다. PDF/DOCX/HWPX/TXT/MD는 추출 본문을 읽습니다. TXT/MD는 **텍스트 편집**에서 UTF-8 원본을 직접 저장합니다. 다른 문서는 **새 초안으로 편집**합니다.
4. **AI 문서 작성 → 직접 작성하기**로 인터넷 없이 블록 초안을 만듭니다. 초안 저장은 앱 DB에 저장하며, DOCX/HWPX/PDF/TXT/MD 출력은 별도 파일 저장입니다. AI 수정안은 적용·거절할 수 있습니다.
5. **문서 관리**에서 연결 폴더의 파일을 찾습니다. 미리보기의 이름 변경·파일 이동·휴지통 명령은 실제 디스크 작업이며, 이동은 연결 범위의 같은 볼륨 안에서 수행합니다. 다른 볼륨은 탐색기를 사용합니다. 상단 **새 문서**나 메뉴의 **새 텍스트 파일**로 현재 폴더에 문서를 만듭니다.
6. 상단에서는 파일 이름을 찾고, **AI 채팅**의 한 입력창에서 본문 검색과 질문을 함께 처리합니다. 관련 문서를 먼저 표시하고 같은 대화에 AI 답변·인용을 붙입니다. 검색 설정 아이콘으로 현재·과거·기준일 범위를 고릅니다. AI가 연결되지 않아도 찾은 문서는 열 수 있습니다. 본문 처리 중 하단에서 중단·계속할 수 있고, 재시작 후에도 중단 상태를 유지합니다.
7. 웹·데스크톱이 같은 통합 AI 패널을 사용합니다. 새 대화·검색 설정·전송·원문 열기는 아이콘이며, 마우스를 올리거나 보조 기술로 이름을 확인할 수 있습니다. 로컬 출처를 열면 인용한 스냅샷과 문단을 표시합니다. 추가 질문에도 앞서 검색한 문서를 현재 대화 안에 유지합니다. 검색 결과의 임시 목록은 패널 메모리에, AI 대화와 요약·작성 결과는 이 기기의 DB에 보관합니다.
8. 영역 선택 후 **요약 파일 만들기**는 선택한 최대 8개 문서의 발췌문으로 새 Markdown 파일과 출처 연결을 만듭니다. 실패 후 결과 저장을 재개할 수 있으며, 처리 여부가 불명확한 AI 요청은 자동 재전송하지 않습니다.

**연결한 폴더 전체 해제**는 왼쪽 **내 컴퓨터**의 폴더 이름 오른쪽 연결 해제 아이콘을 누릅니다. 해당 폴더와 모든 하위 항목이 해당 작업 공간에서 해제되며 원본 폴더·파일은 유지됩니다. 확인 창에서 앱에 보관된 배치·메모·초안·대화·문서 이력·검색 자료의 정리 범위를 확인할 수 있습니다. 다른 폴더를 해제해도 현재 작업은 유지되고, 현재 폴더를 해제하면 남은 연결 폴더로 이동합니다. 마지막 폴더를 해제하면 시작 화면으로 돌아옵니다.

**파일별 연결 해제**는 미리보기 또는 **문서 관리**의 연결 해제 아이콘을 누릅니다. 원본 파일·앱의 기존 이력·배치·연결선은 보존하고 캔버스와 새 본문 검색·AI 문서 검색에서 제외합니다. 새로고침·재시작·원본 이름 변경 후에도 해제 상태를 유지합니다. **문서 관리 → 연결 해제한 파일** 아이콘에서 목록을 열고 플러그 아이콘으로 다시 연결하면 기존 위치와 이력·연결선이 복원됩니다. 기존 대화의 인용은 보관된 스냅샷으로 열 수 있습니다.

**AI 참조**는 답변 아래 화살표로 참조 목록을 펼칩니다. 인용 번호를 누르면 해당 근거까지 자동으로 펼칩니다. 참조 목록을 열고 닫는 것만으로 캔버스를 다시 움직이지 않습니다. 캔버스에서는 주변 파일·메모·폴더·연결선과 기존 좌표를 유지하고, 카메라만 참조한 파일 위치로 확대합니다. **참조 보기 종료**로 확대 전 화면에 돌아갑니다. 참조 확대는 저장된 배치·카메라를 덮어쓰지 않습니다.

파일의 현재 바이트와 검색에 사용할 현재 수정 이력은 분리합니다. 다른 문서의 이력을 연결하거나 과거 이력을 현재로 지정해도 원본 파일을 교체하지 않습니다. **원본 복원**은 확인 후 디스크 파일을 교체하며 교체 전 내용도 이력에 남깁니다. **원본 파일을 현재 이력으로**를 누르면 현재 지정 고정을 풀고 실제 파일을 검색 기준으로 사용합니다.

캔버스는 작업 영역 상단 끝까지 이어집니다. 웹과 같은 `WorkspaceHeader`의 큰 제목·검색·아이콘이 투명하게 그 위에 떠 있습니다. 아이콘 사이의 빈 공간에서는 캔버스를 끌 수 있습니다. 하단 보기 도구와 수정 시 추가되는 텍스트·도형·연결 도구는 오른쪽으로 이어지는 하나의 가운데 정렬 행입니다. 좁은 화면에서는 행 안에서 가로로 스크롤합니다. 하단 안내 문구와 좌측 새 파일 버튼, 파일 가운데 큰 그림은 제거하고 이미지 미리보기·확장자·상태는 유지합니다. 새 문서는 상단이나 문서 관리에서 만듭니다.  새로 여는 파일·폴더와 검색 결과는 도구 아래에 보이도록 화면을 맞춥니다. 편집 기록과 폴더 박스 이동·파일 드롭은 기존 캔버스 상태를 그대로 사용합니다.

## 카드에서 형식 변환·복사본 생성

파일 카드에 마우스를 올리거나 키보드로 초점을 맞추면 웹과 같은 형식 변환·복사본 생성 아이콘이 표시됩니다. 폴더 안에서도 사용하며 드래그 중에는 아이콘을 숨깁니다.

- **형식 변환:** PDF·DOCX·HWPX·TXT·Markdown 문서의 수정 이력을 선택해 5종 형식으로 변환합니다. 결과는 앱에 보관하고 카드 왼쪽에 원본 이력과 함께 표시합니다. 저장 아이콘을 눌러 원하는 위치에 저장하며, 저장 취소는 결과를 지우지 않습니다. 미리보기의 **내보내기**도 같은 변환 기록을 사용합니다.
- **복사본 생성:** 이미지·기타 일반 파일도 원본과 같은 물리 폴더에 `이름 copy.ext`, `이름 copy 2.ext`로 만듭니다. 원본과 독립적으로 수정할 수 있으며 원본을 덮어쓰거나 원본과 하드링크로 연결하지 않습니다. 문서는 현재 수정 이력을 복사하므로 검색 기준으로 고정한 이력이 있으면 그 내용을 사용합니다. 지원하지 않거나 처리에 실패한 파일은 디스크 바이트를 복사합니다. 폴더·바로가기·특수 파일은 제외합니다.
- 복사본은 원본 근처에 배치하고 필요한 이웃만 기존 애니메이션으로 움직입니다. 배치 실행 취소는 생성한 실제 파일을 삭제하지 않습니다. 원본 파일·수정 이력·계정 상태는 유지합니다.

변환 결과와 대기 작업은 `workspace.sqlite`의 `local_conversions`에 저장합니다. 같은 수정 이력·형식·변환기 fingerprint의 결과를 재사용하고, 앱을 닫아 중단된 변환은 다음 실행에 재개합니다. 실패는 화면에서 명시적으로 재시도합니다. 원본 이미지와 정밀한 배치를 복원하지 않으며 OCR·구형 HWP·이미지 형식 변환은 포함하지 않습니다. 원본과 출력은 기존 문서 처리 한도인 50MB를 따릅니다. 일반 파일 복사는 스트리밍하며 이 변환 한도를 적용하지 않습니다.

복사 작업 기록은 `local_copy_requests`에 보관합니다. 중복 요청과 게시 후 앱 중단을 복구하며, 이름 충돌·원본 변경·읽기 전용 폴더에서 원본을 보존합니다. 임시 복사/저장 파일은 숨김 파일 표시 여부와 관계없이 앱 목록과 색인에서 제외합니다. 전체 폴더 연결 해제는 해당 변환 캐시·작업 기록도 정리하고 디스크의 원본과 생성한 복사본은 유지합니다.

SQLite는 버전 9로 올리며 기존 작업 공간이 있으면 먼저 일관된 백업을 만듭니다. 변환·복사는 로그인·서버·AI 호출 없이 로컬에서 수행하며 자동 웹 동기화를 시작하지 않습니다.

## 웹과 같은 계정으로 로그인

폴더를 연결하기 전에도 왼쪽 아래 **로그인 → Google로 계속하기**를 사용할 수 있습니다. 시스템 브라우저에서 웹과 같은 Google 계정을 선택하면 앱으로 돌아옵니다. 로그인하지 않아도 폴더·캔버스·문서 검색·직접 작성은 계속 사용할 수 있습니다.

기본 API 주소는 `http://127.0.0.1:8000`입니다. 로그인 창의 **서버 설정**에서 바꾸거나 실행 환경의 `CONTEXT_SERVER_URL`로 초기 주소를 지정합니다. 이미 저장한 서버 주소가 있으면 그 값을 유지합니다. HTTPS와 loopback HTTP만 허용합니다.

앱은 서버가 검증한 `/api/me`의 웹 사용자 UUID·이메일·이름을 사용합니다. 앱 계정과 기본 ChatKHU는 같은 세션을 공유합니다. 기존 AI 연결 계정은 시작 시 계정 정보를 확인해 일반 계정 표시로 이어집니다. 개인 ChatKHU 키와 선택한 모델은 로그인·로그아웃으로 지우지 않습니다.

세션은 OS 보안 저장소로 암호화한 `userData/ai-connection.enc`에 보관하며 토큰은 화면·브라우저 저장소·로컬 변경 로그에 전달하지 않습니다. 재실행·절전 복귀와 주기적 확인 시 계정을 갱신합니다. 오프라인/만료 상태를 표시해도 로컬 파일 작업은 유지합니다. 로그인 취소는 임시 callback 서버와 진행 중인 요청을 닫습니다. 로그아웃은 이 기기의 연결을 제거하고 해당 세션만 해제합니다.

로그인·계정 변경·로그아웃은 파일·폴더 연결·배치·초안·대화를 이동하거나 삭제하지 않습니다. 자료를 계정에 자동 귀속하거나 웹으로 업로드하지 않습니다. 아래 수동 동기화를 선택할 때 검증된 웹 사용자 UUID로 별도 연결합니다.

## 클라우드 동기화

로그인한 뒤 폴더 화면의 **클라우드 동기화 → 지금 동기화**를 누릅니다. 처음에는 계정·서버와 전송 범위를 확인합니다. 연결된 일반 파일과 원본 수정 이력, 중첩·빈 폴더, 배치·메모·도형·연결선, 작성 초안을 전송합니다. 파일별 연결 해제 항목과 AI 대화, 개인 키·로그인 토큰·로컬 절대 경로·뷰포트는 전송하지 않습니다.

완료 후 **웹에서 열기**로 같은 계정의 작업 공간을 엽니다. 웹에서 폴더를 탐색하고 원본·수정 이력·메모·초안을 확인하며 검색과 새 AI 채팅을 사용할 수 있습니다. 원본·배치·초안 수정은 데스크톱에서 수행합니다. 다음 동기화는 전체 metadata를 다시 확인하고 서버에 없는 버전 바이트만 업로드합니다.

**전송 중단** 후 다시 누르면 같은 스냅샷을 이어서 전송합니다. 전송 대기 중 새로 수정한 내용은 다음 동기화에 포함합니다. **현재 내용으로 다시 준비**는 미완료 세션을 취소하고 최신 내용을 다시 준비합니다. 완료 응답이 유실됐다면 먼저 기존 반영 결과를 확인합니다. **동기화 연결 해제**는 원본과 기존 클라우드 자료를 보존합니다. 폴더 전체의 로컬 연결 해제도 원격 삭제를 뜻하지 않습니다.

원본 누락은 보관한 버전으로 유지하며, 폴더 자체에 접근할 수 없으면 전송을 시작하지 않습니다. 현재는 로컬 작업 공간 하나를 하나의 서버·계정에 연결합니다. 다른 계정으로 자동 이전하지 않습니다. 파일당 50MiB, 기본 작업 공간 원본·이력 합계 2GiB를 적용합니다. 바로가기·특수 파일은 제외합니다. 동기화 원본을 먼저 저장한 뒤 서버에서 지원 문서의 본문과 검색 색인을 준비합니다.

백엔드 migration `0013_cloud_sync`와 S3 설정이 필요합니다. 운영 서버의 `WEB_BASE_URL`에는 웹 프런트 주소를 지정합니다(비우면 첫 CORS origin). [서버 구조·API·검증](../../docs/cloud-sync-implementation.md)을 참고합니다.

## AI 연결

**내 ChatKHU:** AI 연결 설정에서 개인 API Gateway 키를 저장하고 **연결 확인 · 모델 불러오기**를 누른 뒤 모델을 선택·저장합니다. 키는 macOS/Windows의 Electron 보안 저장소로 암호화합니다. 사용 가능한 보안 저장소가 없으면 평문으로 저장하지 않습니다. ChatKHU 비밀번호·쿠키를 요구하지 않습니다.

**기본 ChatKHU:** ConText 서버 주소를 저장하고 **Google로 계정 연결**을 진행합니다. 시스템 브라우저와 PKCE를 사용합니다. 브라우저 연결을 취소할 수 있습니다. 모델 목록을 불러와 해당 서비스 계정에서 허용된 모델을 선택합니다. 개인 연결 실패 시 기본 연결로 자동 전환하지 않습니다.

로컬 개발 서버는 저장소 루트의 기존 `.env.development`를 유지한 채 실행합니다.

```bash
docker compose --env-file .env.development up --build -d
```

데스크톱 서버 주소는 `http://127.0.0.1:8000`입니다. 운영 서버는 HTTPS를 사용합니다. 백엔드에는 ChatKHU 서비스 키, Supabase URL·공개 키, 개인 키/짧은 요청 결과를 암호화할 `AI_CREDENTIALS_KEY`, 일일 사용량 제한이 필요합니다. `.env.development.example`과 `.env.backend.production.example`을 참고합니다. 서버 시작 시 Alembic migration을 실행합니다.

Supabase 프로젝트의 Redirect URLs에는 데스크톱 loopback callback도 허용해야 합니다. 이 구현의 형태는 `http://127.0.0.1:<임시 포트>/callback/<임의 경로>`이며, 개발 허용 패턴은 `http://127.0.0.1:*/callback/*`입니다. 기존 웹 callback도 유지합니다. 패턴의 의미는 [Supabase 공식 문서](https://supabase.com/docs/guides/auth/redirect-urls)를 따릅니다. 현재 로컬 서버의 공개 설정과 개발·운영 웹이 같은 인증 프로젝트를 사용하는 것을 확인했습니다. 공개 OAuth 시작 후 사용자 없는 취소 callback 검사로 현재 프로젝트가 데스크톱 주소로 돌아오는 것도 확인했습니다. 실제 사용자 계정의 Google 선택·동의·로그인 완료는 자동화하지 않았습니다.

모델 목록은 연결 계정의 [ChatKHU `/models` 응답](https://docs.mindlogic.ai/docs/khu/api-gateway/getting-started/models)을 사용합니다. 최신 모델 이름을 고정하지 않습니다. 실제 서비스 계정에서 `gpt-5.6-luna`의 합성 문장 호출을 확인했으며, 개인 실계정 호출은 미검증입니다.

AI에는 필요한 발췌문·정확한 문서/버전 참조·현재 초안을 전송합니다. 원본 전체 파일이나 로컬 경로·키를 AI 요청 payload에 넣지 않습니다. 기본 AI 중계는 로컬 자료를 서버 문서 저장소에 영구 등록하지 않습니다. 파일 원본 전송은 위의 수동 클라우드 동기화를 선택한 경우에만 수행합니다.

## 저장·복구

`app.getPath('userData')/workspace.sqlite`에 메타데이터·배치·초안·대화·본문 색인·불변 버전 스냅샷을 저장합니다. 읽은 문서의 원본 바이트도 버전 보존용으로 앱 DB에 저장합니다. 원본 폴더를 별도 작업 공간으로 통째로 복사하지 않습니다. 이미지 썸네일은 메모리에만 캐시합니다.

DB는 순차 마이그레이션 전에 일관된 SQLite 백업을 `backups` 폴더에 만듭니다. 앱이 실행 중인 DB 파일 하나만 복사해 백업하지 마세요. 복구 시 앱을 종료한 뒤 백업과 현재 DB·WAL을 함께 보존하고 백업 복사본으로 작업합니다.

파일 저장은 임시 파일 fsync·원본 해시 확인·저장 journal을 사용합니다. 중단된 저장이 있으면 다음 실행에 복구 항목이 나옵니다. **작성 내용 복구**, **저장 전 자료 복구**로 별도 파일을 보관합니다. **확인 완료**는 항목 표시를 마치며 임시 자료를 삭제하지 않습니다. 외부 변경 충돌 시 편집안은 화면에 남고 원본을 덮어쓰지 않습니다.

**폴더 설정의 연결 해제**는 확인 후 해당 작업 공간 전체의 앱 내부 초안·이력·색인·대화·배치를 지웁니다. 파일별 연결 해제는 이 자료를 삭제하지 않고 로컬 연결 상태만 저장합니다. 원본 폴더와 내보낸 파일, 이전 마이그레이션 백업은 유지됩니다. 미완료 저장의 복구 자료도 폴더에 남으므로 연결 해제 전에 복구 화면에서 확인합니다. 외장 드라이브 해제나 읽기 실패는 원본 삭제로 처리하지 않습니다.

## 범위

- 본문 처리: TXT/MD/PDF/DOCX/HWPX, 문서당 최대 50MB. 직접 원본 편집은 2MB 이하 UTF-8 TXT/MD이며 BOM과 기존 CRLF를 보존합니다. 혼합 줄바꿈은 CRLF가 포함되어 있으면 CRLF로 정규화합니다.
- 이미지: PNG/JPEG/WebP/GIF/BMP, 20MB 이하. 애니메이션은 정지 미리보기입니다.
- HWP 바이너리·스캔 PDF OCR·원본의 정밀 배치/이미지 보존 편집은 지원 범위 밖입니다. 변환은 추출 텍스트·제목·목록·표 중심입니다.
- 링크와 특수 파일은 직접 읽지 않으며, 경로 이탈·다른 작업 공간의 ID를 거부합니다. 실행 파일·스크립트는 원본 열기로 실행하지 않습니다.
- 작업 공간 메타데이터 최대 25,000개, 화면은 폴더·파일을 합쳐 200개씩 표시합니다. 진입한 폴더의 조상 영역과 직계 항목을 우선 표시하며 **다음 200개 표시**로 범위를 늘립니다. AI 참조가 표시 범위 밖에 있으면 기존 항목을 유지하면서 인용 파일과 조상 폴더만 임시로 추가합니다. 본문은 증분 처리하지만 파일 감시 후 메타데이터는 전체 재확인합니다. 합성 파일 2,012개·본문 4,812구간으로 측정했으며 최대 규모의 장시간 부하 검증은 남아 있습니다.
- Windows 설정은 준비했으며 실제 설치·실행·키 저장 검증은 Windows에서 수행해야 합니다. 실시간 공동 편집·양방향 웹 동기화·서명/공증·자동 업데이트는 후속 범위입니다.

## 검증·패키징

```bash
npm test
npm run test:e2e
npm run pack
```

`pack`은 현재 OS의 앱 폴더를 만듭니다. 파서 소스를 바꾸면 `processor:build`도 먼저 실행합니다. 현재 macOS Apple Silicon 출력 경로는 다음과 같습니다.

```text
release/mac-arm64/ConText Desktop.app
```

```bash
open "release/mac-arm64/ConText Desktop.app"
CONTEXT_DESKTOP_EXECUTABLE="$PWD/release/mac-arm64/ConText Desktop.app/Contents/MacOS/ConText Desktop" npx playwright test
```

현재 패키징 앱은 두 손가락 캔버스 이동·핀치 확대, 오른쪽 AI 패널 전환, 폴더별 중첩 탐색과 수정 상태의 한 번 클릭 펼치기, 텍스트 겹침과 새 파일·폴더의 주변 배치를 포함합니다. 새 항목은 이웃을 가로로 조금씩 움직이며 저장·배치 undo/redo를 지원합니다. 실행 취소해도 생성한 실제 파일은 보존합니다. 깊게 확대한 화면도 재시작 후 복원하고 이후 더 확대할 수 있습니다.

형식 변환·복사본 추가 후 최종 패키징 앱 전체 20개 E2E와 단위·로컬 통합 73개가 통과했습니다. 공통 변환·복사 UI는 웹·모바일 17개 검사도 통과했습니다(모바일 호버 전용 1개 제외). 이전 캔버스 단계의 웹·모바일 통합 회귀 73개(모바일 트랙패드 1개 제외), 확대 보완 6개, 업로드 복구 12개, 캔버스 40개, 복사본 2개와 웹 빌드·타입·린트도 통과했습니다. 중복 시나리오는 합산하지 않습니다. 상세 명령·로그·화면은 [검증 기록](../../docs/desktop-web-parity-verification.md)을 따릅니다.

`release/parity-build.json`에 소스·renderer·app.asar SHA-256과 파서 fingerprint를 기록했습니다. 검증 후 런타임 소스를 바꾸면 다시 패키징·검사해야 합니다. 서명·공증되지 않은 개발 빌드입니다. 검사는 임시 폴더와 프로필을 사용하며 패키징 앱은 `--user-data-dir`로 테스트 자료를 분리합니다.

수동 클라우드 동기화 추가 후 macOS 최종 패키징 앱의 기존 20개와 동기화 1개 E2E, 웹·모바일 동기화 4개와 서버 221개 검사를 통과했습니다. `release/cloud-sync-build.json`에 앱·renderer·런타임 소스 해시를 기록합니다. 실제 AWS의 만료 임시 파일 정리 권한은 추가 설정이 필요하며, [새 검증·운영 기록](../../docs/cloud-sync-implementation.md)을 따릅니다.

후속으로 웹 목록과 데스크톱 동기화 메뉴에 **클라우드 워크스페이스 삭제**를 추가했습니다. 로컬 원본과 앱 자료는 유지하며 모든 멤버의 웹 접근과 이후 전송을 차단합니다. 기존 ‘폴더 연결 해제’는 이 기기의 앱 자료만 제거하고 클라우드 자료를 유지합니다. 삭제 범위·제한과 최신 검증은 [동기화 점검 기록](../../docs/web-desktop-sync-audit.md)을 따릅니다.
