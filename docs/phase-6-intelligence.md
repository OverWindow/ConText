# Phase 6 — 버전 변경 분석과 후보 추천

## 사용법

- 문서를 열어 **버전 비교 → 두 버전 선택 → 비교하기**를 누른다. 추가·삭제·수정 개수와 문단별 변경 내용, 단어 단위 강조를 확인할 수 있다. 제목 단계·표 구조도 비교한다. 문서 위치는 블록 번호와, 추출된 경우 페이지 번호로 표시한다.
- **AI 변경 요약**의 근거 링크로 실제 변경 문단으로 이동한다. AI 해석은 원문과 함께 확인한다. 자동 분석이 아직 없거나 실패한 경우 OWNER/EDITOR는 **AI 요약 요청**을 누를 수 있다.
- **버전 후보**는 현재 미리보기 중인 버전을 같은 워크스페이스의 다른 문서와 비교한다. 다른 버전을 대상으로 분석하려면 버전 이력에서 먼저 선택한다.
- 후보의 **‘문서명’의 새 버전으로 등록**은 사용자가 명시적으로 선택할 때만 실행된다. 기존 Phase 5 수동 연결을 사용해 원본 문서·파일과 출처 ID를 보존한다. 대상 문서의 현재 버전은 자동 변경하지 않는다. 대상 문서의 버전 이력에서 따로 지정한다.
- 후보를 선택하지 않으면 별도 문서로 유지된다. 동일 파일은 중복으로 표시하고 또 연결하는 버튼은 제공하지 않는다.
- VIEWER는 저장된 분석과 후보를 조회할 수 있다. 외부 AI 호출 요청·재시도·버전 연결은 OWNER/EDITOR만 가능하다.

## AI 연결

`.env.development` 또는 실행 환경에 다음 서버 전용 설정을 추가한다. 실제 키를 문서, 코드 또는 브라우저 환경 변수에 넣지 않는다.

```dotenv
MINDLOGIC_API_KEY=<발급받은 키>
MINDLOGIC_BASE_URL=https://factchat-cloud.mindlogic.ai/v1/gateway
AI_MODEL=gpt-5.6-luna
AI_EMBEDDING_MODEL=text-embedding-3-small
```

키를 제외한 세 값은 코드/Compose에 기본값이 있다. 임베딩 모델은 계정에서 사용 가능한 다른 모델로 바꿀 수 있다. 기본값은 공식 [임베딩 API 문서](https://docs.mindlogic.ai/docs/general/api-gateway/reference/embeddings)의 지원 모델을 기준으로 정했다. 요약은 공식 [Chat Completions 문서](https://docs.mindlogic.ai/docs/general/api-gateway/reference/chat-completions)의 경로와 메시지·출력 형식을 사용한다. OpenAI 서비스로 직접 요청하지 않는다.

설정 후:

```bash
docker compose --env-file .env.development up -d backend worker dispatcher
```

기존 미설정 상태로 완료된 분석은 해당 화면의 **후보 분석 요청 / AI 요약 요청**으로 재시도한다. 후보의 의미 비교는 비교 대상 문서의 해당 버전에도 임베딩 분석이 완료되어 있어야 한다. 실패·미설정 결과 재시도는 마지막 완료 후 30초 간격이다. 이미 성공한 결과는 같은 요청에서 재사용한다.

현재 검증 환경에는 실제 Mindlogic 키가 없다. 텍스트 차이와 텍스트 기반 추천은 동작하며 AI 미설정을 별도로 표시한다. 외부 API의 실제 계정 권한·과금·응답 품질은 아직 검증하지 않았다.

## 처리와 저장

- `analysis_jobs` (`0007_version_intelligence`)는 파일 처리와 독립적인 DB outbox다. 프로필 작업은 버전당 하나, 변경 요약 작업은 순서 있는 두 버전 쌍당 하나다. PostgreSQL 충돌 방지 삽입으로 동시 요청을 합친다.
- dispatcher가 READY 버전을 발견해 프로필 작업을 자동 생성한다. Phase 6 이전 문서도 배치당 최대 50개씩 채운다. 직전 버전 번호의 문서 처리까지 완료되면 변경 요약을 자동 생성한다. 업로드/파싱 완료 순서가 역전되어도 직전 번호를 건너뛰지 않는다.
- 임의의 두 READY 버전은 일반 diff를 즉시 조회할 수 있고, 편집자는 그 쌍의 요약을 요청할 수 있다. 같은 문서 소속 여부와 워크스페이스 권한을 검사한다.
- Celery 작업은 토큰으로 실행 소유권을 확인해 오래된 실행 결과가 새로운 결과를 덮어쓰지 못하게 한다. 파일/S3 분석 오류는 최대 3회, 중단된 작업은 180초 뒤 복구하며 Redis 전송 실패는 DB 작업을 보존한다.
- AI 서비스 미설정·호출 실패·잘못된 응답은 분석 결과의 경고로 저장한다. 결정적 diff와 파일 READY 상태를 보존하고 사용자가 재시도할 수 있게 한다. AI 결과가 없을 때 가짜 요약이나 임베딩을 만들지 않는다.
- `AIService → AIProvider → MindlogicProvider`로 분리했다. HTTPS와 Bearer 인증을 사용하고 리다이렉트는 따르지 않는다. 응답 크기·벡터·JSON 구조·근거 ID와 변경 종류를 검증한다. 게이트웨이 응답이나 키를 로그/오류 메시지에 기록하지 않는다.
- 원본 SHA-256, 비교 기준 SHA-256, 모델, 프롬프트·알고리즘 버전, 완료 시각을 보존한다. 모델에 전달한 변경 ID도 보존한다. 프롬프트는 문서 내 지시를 분석 대상으로 취급하고 실행하지 않도록 구성했다. 서버는 모델 출력을 도구/명령으로 실행하지 않는다.
- 정규화된 원본은 S3에 유지한다. DB에는 제한된 텍스트 표본·벡터·diff·요약만 저장한다. 표본과 벡터는 API에 직접 노출하지 않는다. 분석 캐시는 버전 삭제에 연동된다. RAG용 chunk/pgvector 검색은 Phase 7 범위다.

## 범위와 제한

| 기능 | 범위 |
|---|---|
| 블록 비교 | 각 문서 앞 1,200블록, 텍스트 60,000자 |
| 변경 표시 | 최대 120개, 문단당 앞 1,500자; 생략 여부 표시 |
| AI 요약 입력 | 변경 근거 JSON 최대 약 16,000자; 유지 문단 제외 |
| 프로필 | 추출 텍스트 앞 12,000자; 표본 여부 표시 |
| 버전 후보 | 같은 workspace의 다른 문서 중 현재 READY 버전, 최근 500개; 최대 5개 추천 |
| 의미 유사도 | 같은 endpoint·모델·표본 알고리즘의 임베딩만 cosine 비교 |

텍스트 유사도는 한글을 포함하는 문자 3-gram cosine이다. 종합 점수는 `0.85 × max(텍스트 유사도, 임베딩 유사도) + 0.15 × 파일명 유사도`이며 정확한 SHA-256/크기 중복은 1이다. 텍스트 또는 의미 유사도 0.55 이상, 종합 0.6 이상인 후보만 추천한다. 파일명만으로 추천하지 않는다. 점수는 확률이 아니며 일부 표본·현재 버전만 비교하므로 같은 문서라는 판정의 근거로 단독 사용하지 않는다.

구조/단어 diff는 추출된 정규화 결과를 비교한다. 글꼴·색상·픽셀·페이지 레이아웃 차이, OCR은 범위 밖이다. 문단 이동은 삭제/추가로, 연속 교체 구간은 순서대로 수정으로 표현할 수 있다. 큰 문서의 뒷부분은 누락될 수 있고 이 경우 전체 동일성을 주장하지 않는다. 인용 ID 검증은 모델 해석의 사실성을 보장하지 않으므로 원문 근거 확인을 제공한다.

## API

모든 경로는 `/api` prefix를 사용하며 인증과 workspace membership을 검사한다. 응답은 `Cache-Control: no-store`다.

| Method | 경로 | 기능 |
|---|---|---|
| GET | `/documents/{id}/diff?left={version}&right={version}` | 결정적 문단/단어 diff |
| GET | `/documents/{id}/changes?left={version}&right={version}` | 저장된 AI 변경 분석 상태·결과 |
| POST | `/documents/{id}/changes` | `{left, right}` 분석 생성/재시도, 202 |
| GET | `/versions/{id}/intelligence` | 프로필 상태 + workspace 내 버전 후보 |
| POST | `/versions/{id}/analyze` | 프로필 생성/재시도, 202 |

새 업로드/수동 연결 시 원래의 parsing 흐름은 유지한다. 분석 상태가 파싱 상태를 변경하지 않는다. migration downgrade는 `analysis_jobs`만 제거하며 원본 문서/버전은 유지한다.

검증 명령과 실제 실행 결과는 [Phase 6 검증 기록](phase-6-verification.md)에 있다.
