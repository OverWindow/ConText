# 캔버스 텍스트와 배경 도형

Phase 5 이후의 캔버스 편집 확장이다. AI Version Intelligence(Phase 6) 구현과는 별개다.

## 사용법

- 상단 **연필 아이콘(캔버스 수정)**을 누르면 수정 모드가 켜지고 텍스트·도형 도구와 연결 편집 설정이 나타난다. 기본 화면과 새로고침 직후에는 둘러보기 모드다.
- 수정 모드에서 캔버스 아래 도구의 **텍스트**를 누르면 현재 보이는 영역에 텍스트 상자가 생긴다. 선택한 상자에 직접 내용을 적는다. 줄바꿈을 지원한다.
- **사각형·타원·삼각형** 아이콘으로 기본 배경 도형을 추가한다. 도형은 문서 카드와 텍스트 뒤에 유지되며 선택해도 앞쪽으로 올라오지 않는다.
- 요소를 선택한 뒤 모서리·변 핸들을 끌어 크기를 조절한다. 오른쪽 편집 도구의 너비·높이를 입력할 수도 있다.
- 텍스트는 이동 손잡이(데스크톱 위쪽·모바일 아래쪽)로, 도형은 본체를 끌어 이동한다. 텍스트를 선택하지 않은 상태에서는 본체를 끌어도 된다.
- 6종 색상과 텍스트 글자 크기를 조절할 수 있다. **요소 삭제**로 선택한 텍스트나 도형만 삭제한다.
- 내용·위치·크기·색상·글자 크기는 자동 저장한다. 오류 안내가 나오면 **텍스트·도형 저장 재시도**를 누른다. 저장 완료 표시를 확인한 뒤 페이지를 이동한다.
- 상단 체크 아이콘(**캔버스 수정 완료**)을 누르면 편집 도구·리사이즈 핸들·연결 옵션이 닫힌다. 저장 대기 중인 변경은 계속 저장하며 실패 안내와 재시도 버튼은 유지한다.
- 문서 카드·텍스트·도형 이동도 수정 모드에서만 가능하다. 둘러보기 모드에서도 문서 클릭 미리보기, 검색, 확대·축소와 캔버스 탐색을 사용할 수 있다.
- OWNER/EDITOR는 수정 모드 진입이 가능하고 VIEWER는 열람만 가능하다. 페이지 스크롤 금지·전체 화면 격자·문서 미리보기는 유지한다.

크기 제한은 너비 80~2,000, 높이 60~2,000 캔버스 단위이며 글자 크기는 12~96px다. 텍스트는 최대 5,000자, 워크스페이스당 요소는 최대 500개다. HTML이나 외부 SVG를 삽입하지 않고 일반 텍스트와 고정된 기본 도형만 렌더링한다. 텍스트 상자가 작으면 선택한 편집 상자 안에서 스크롤할 수 있다.

## 사각형 폴더 — 2026-10-17

사각형 배경은 파일을 포함하는 캔버스 폴더로 표시한다. 수정 모드에서 폴더 아이콘으로 생성하고, 하단 안쪽 이름을 선택해 편집한다. 이름은 기존 요소 text 필드로 저장하므로 DB 변경은 없다. 파일 카드가 완전히 들어온 영역을 기준으로 묶이며, 겹칠 때 가장 작은 폴더가 우선한다. 폴더 삭제는 문서를 삭제하지 않는다.

보기 모드의 배율 38% 미만에서는 내부 파일 대신 배경 중앙에 이름과 파일 수를 표시한다. 작은 영역에서는 이름을 우선한다. 이름 영역은 배경 밖으로 나가지 않으며, 폴더를 클릭하거나 확대하면 파일이 다시 보인다. 수정·영역 선택·검색·AI 참조 중에는 개별 파일을 유지한다. 폴더 이름으로도 내부 문서를 검색할 수 있다.

이름 오버레이는 React Flow NodeToolbar로 표시해 파일이나 텍스트 뒤에 가리지 않으며, 화면에서 읽을 수 있는 글자 크기를 유지한다. 포함 관계는 저장된 도형·문서 위치로 다시 계산하는 공간 기반 그룹이다. 새 폴더 기본 크기는 640×420이며, 이름은 최대 80자다.

## 문서 연결

왼쪽의 기존 **문서 연결** 메뉴와 전체 연결 목록 패널은 제거했다.

- 수정 모드에서 문서 양쪽 연결점을 드래그해 새 연결을 만든다. 요소 선택을 해제한 상태에서 하단 **새 연결 유형**으로 참조·파생·생성 출처·관련 문서를 선택한다.
- 기존 연결선을 누르면 클릭한 위치 근처에 **연결 옵션**이 뜬다. 출발·도착 문서와 관계 종류를 확인하고 **연결 삭제**를 누르면 바로 삭제된다. 문서 자체는 유지된다.
- 삭제가 실패하면 옵션창을 유지하고 오류를 표시해 다시 시도할 수 있다.
- 옵션창 밖을 누르거나 Escape, 닫기 버튼, 수정 완료로 닫는다. 둘러보기 모드와 VIEWER에게는 삭제 옵션이 나오지 않는다.
- 연결선 표시 체크박스와 상단 참조 라벨 표시 아이콘은 데이터를 지우지 않고 표시만 조절한다.

## 구조와 API

`0006_canvas_elements` migration은 workspace 소속 `canvas_elements` 테이블을 추가한다. 번호 0006은 DB migration 순번이며 프로젝트 Phase 6 완료를 뜻하지 않는다. 문서/버전과 독립적이고 RAG나 문서 파싱 대상으로 등록하지 않는다.

| Method | 경로 | 동작 |
|---|---|---|
| GET | `/api/workspaces/{id}/canvas` | 기존 snapshot에 elements 배열 추가 |
| POST | `/api/workspaces/{id}/canvas/elements` | 요소 생성 |
| PATCH | `/api/workspaces/{id}/canvas/elements/{element_id}` | 내용·위치·스타일 부분 수정 |
| DELETE | `/api/workspaces/{id}/canvas/elements/{element_id}` | 요소 삭제 |

생성 필드: 클라이언트 UUID `id`, `kind`(text/rectangle/ellipse/triangle), `x`, `y`, 선택적 `text`, `width`, `height`, `color`, `font_size`. 각 요소에 작성자·최종 수정자·시각을 저장한다. 생성 재시도는 같은 ID와 같은 내용이면 같은 요소를 반환한다. 같은 ID의 다른 내용은 409다. 부분 수정은 다른 필드를 덮어쓰지 않는다. 모든 API는 기존 Supabase 인증과 워크스페이스 권한을 검사한다. 요소 ID만 알아도 다른 워크스페이스의 요소를 수정할 수 없다.

React Flow 커스텀 노드와 NodeResizer를 사용한다. 도형을 가장 뒤에, 문서 카드를 그 위에, 텍스트를 맨 앞에 배치한다. 텍스트·도형 저장 큐는 문서 좌표 큐와 분리하고, 실패한 변경 및 저장 중 새 편집을 유지한다. 새로고침 요청의 늦은 응답이 편집 중인 내용을 덮어쓰거나 삭제된 요소를 되살리지 않도록 보호한다. 여러 사람이 같은 필드를 동시에 수정하면 마지막으로 저장된 값이 적용된다. 실시간 공동 타이핑은 구현하지 않는다.

## 실행

추가 의존성·환경 변수·외부 서비스 설정은 없다. 현재 경로의 소스를 수정했고 Docker bind mount에 반영한다.

```bash
docker compose --env-file .env.development exec -T backend alembic upgrade head
```

새 환경에서는 기존 `docker compose --env-file .env.development up --build` 명령으로 시작하면 된다.

## 수정 모드 후속 변경

### 파일을 폴더에 놓을 때 자동 확장

사각형은 저장된 영역으로 내부 파일을 묶는 공간 폴더다. 수정 모드에서 파일 중심을 사각형 안이나 테두리 바깥 40px 이내에 놓으면 파일 전체와 여백을 담도록 사각형 위치·크기를 확장한다. 실제 내부인 폴더를 먼저 선택하고, 바깥 여유 영역에서는 가장 가까운 테두리를 우선한다. 거리가 같으면 가장 작은 폴더를 선택한다. 외부 파일과 다른 폴더에서 옮긴 파일 모두 동일하게 처리한다. 여유 영역 밖에 놓으면 확장하지 않고, 다른 파일의 위치는 유지한다. 원래 폴더는 남은 파일에 맞춰 축소한다. 빈 폴더의 최소 크기는 320×240px이며 기존 폴더보다 커지지는 않는다. 드래그 중 확장·축소는 화면 미리보기로만 표시하고, 실제 저장은 파일을 놓을 때 수행한다. 원래 자리로 돌아오면 미리보기가 복원된다.

기존 문서 좌표 및 요소 PATCH 저장 큐를 사용하므로 새로고침 후에도 포함 관계가 유지된다. 파일 이동의 되돌리기·다시 실행에는 해당 이동으로 생긴 자동 확장·축소도 함께 기록한다. 크기 저장 실패는 기존 요소 저장 재시도로 처리하고, 되돌리기 저장 실패는 기록을 유지해 다시 시도할 수 있다. API의 최대 너비·높이 2000px를 초과하면 안내하고 확장하지 않는다.

기본 화면에서 편집 도구를 숨기고 연필 아이콘으로 수정 모드를 켜도록 변경했다. 기존 문서 연결 메뉴·상세 연결 목록 패널을 제거하고, 연결선을 직접 눌러 옵션창에서 삭제하는 방식으로 바꿨다. 새 연결 유형 선택과 연결선 표시 설정은 수정 모드 하단 도구에 있다. 변경 범위는 프런트엔드이며 API·DB 스키마·외부 설정 변경은 없다.

ESLint·TypeScript·운영 빌드와 실행 중인 프런트엔드/API HTTP 200 확인도 완료했다. 기존 API를 재사용하는 UI 변경이므로 이번 후속 변경에서는 백엔드 테스트를 다시 실행하지 않았다.
