# ConText 제품 방향

2026-10-28 기준. 초기 팀 문서 관리 중심의 방향을 아래 기준으로 변경한다.

> 내 문서와 AI가 함께 일하는 공간. 내 PC에서 시작하는 AI 문서 작업 공간.

## 제품의 중심

제품의 중심은 **AI와 함께 일하기 좋은 로컬 문서 환경**이다. 평소 쓰던 폴더의 자료 탐색, 파일을 근거로 한 AI 질문, 초안 작성과 문서 편집을 같은 작업 공간에서 제공한다. 사용자는 자신의 자료를 바탕으로 답변과 수정안을 받고, 익숙한 파일에서 작업을 이어간다. 첫 사용의 목표는 **내 자료를 찾고, 묻고, 문서로 정리하는 경험**이다. 채팅은 이 환경에서 작업하는 한 가지 방법이다.

- 주 사용자는 자신의 자료로 업무·학습·글쓰기를 이어가는 개인이다.
- 데스크톱과 기존 로컬 폴더를 기본 시작점으로 둔다. 웹은 자료 접근과 선택적 동기화를 돕는다.
- 문서를 작업의 중심으로 삼고, 자료 탐색·AI 대화·초안 작성·편집과 근거 확인을 연결한다.
- 캔버스·연결선은 자료 탐색을 돕는다. 버전·비교·복구는 적용 결과를 확인하고 되돌리는 기반으로 쓴다.

## 핵심 사용 흐름

현재 소개의 흐름은 **자료 탐색 → AI 질문과 출처 확인 → 초안 작성·수정 → 파일 작업 계속**이다. 경희대 ChatKHU는 AI 연결 기반으로 소개하고, 손쉬운 설치·폴더 선택은 시작 경험으로 설명한다. 아래는 후속 개발로 연결하려는 원본 적용 흐름이다.

1. 평소 쓰던 폴더를 선택한다.
2. 파일을 선택하거나 질문으로 관련 파일을 찾는다.
3. “회의록의 할 일을 담당자별로 정리해 줘”처럼 작업을 요청한다.
4. AI가 대상 파일과 근거, 변경 전후 내용을 제안한다.
5. 사용자가 확인해 적용하고 기존 파일에서 작업을 계속한다.
6. 적용 결과와 변경 이력을 확인하고 필요하면 복원한다.

## 현재 구현과 다음 개발

| 영역 | 현재 가능한 것 | 다음 개발 |
| --- | --- | --- |
| 내 자료로 대화 | 로컬 본문 검색, AI 답변과 인용, 기기 내 대화 보관 | 대화에서 수정 대상 파일을 명확히 선택·유지 |
| 기존 파일 편집 | TXT·Markdown 텍스트 편집에서 UTF-8 원본 저장 | 채팅이 제안한 변경을 비교 후 같은 파일에 적용 |
| AI 수정 | 블록 초안에서 AI 수정안 비교·적용·거절 | 채팅 요청과 파일 수정안을 하나의 흐름으로 통합 |
| 다른 문서 형식 | 기존 내용을 새 초안으로 가져오기, 별도 파일 내보내기 | 형식별 원본 적용 가능 범위를 검증한 뒤 확장 |
| 기록과 복구 | 파일 이력·비교·원본 복원·저장 충돌 처리 | AI 적용 작업과 저장·복구 이력을 연결 |

첫 개발 단위는 **TXT·Markdown 하나를 대상으로 한 채팅 수정 제안 → 전후 비교 → 원본 적용 → 복원**으로 잡는다. 적용 시 대상 경로·기준 파일 해시·수정안을 연결하고, 외부 편집으로 원본이 바뀌었다면 적용을 중단해 다시 비교한다. 기존 저장 journal·스냅샷·복구 구조를 재사용한다.

완료 기준은 사용자가 채팅의 수정 결과를 복사해 붙여넣지 않고 기존 파일에 반영하고, 이력을 통해 이전 내용으로 돌아올 수 있는 것이다. 이후 여러 파일과 문서 형식으로 확장한다. 이번 랜딩 개편은 이 통합 편집 기능을 구현하지 않는다.

## 소개와 화면 원칙

- 대표 문구: **내 문서와 AI가 함께 일하는 공간.**
- 제품 설명: **내 PC에서 시작하는 AI 문서 작업 공간**. 차별점은 쓰던 폴더와 파일을 바탕으로 자료 탐색·AI 질문·문서 작성과 편집을 이어가는 경험이다.
- 랜딩과 영상은 같은 대표 문구를 사용한다. 경희대 ChatKHU는 연결 기반으로, 손쉬운 시작은 설치·폴더 선택·AI 연결의 흐름으로 설명한다.
- 랜딩 첫 화면에는 자료·AI 질문·문서 작업의 흐름과 수정안 비교 예시를 보여주고 데스크톱 다운로드를 우선한다.
- 랜딩의 적용 화면은 개발 방향을 설명하는 상호작용 예시다. 실제 AI 호출이나 파일 읽기·저장을 수행하지 않는다.
- 현재 TXT·Markdown 원본 편집과 초안의 AI 수정을 설명한다. 모든 형식의 원본 수정이 이미 가능한 것처럼 소개하지 않는다.
- 로컬은 파일 작업·기록 보관의 위치를 뜻한다. 현재 AI 답변은 연결한 외부 AI를 사용하고 필요한 발췌문을 전송한다. 완전 오프라인 AI 실행을 의미하지 않는다.

## 우선순위

1. 채팅에서 대상 파일을 지정하고 수정안을 비교하는 UI.
2. TXT·Markdown 원본 적용, 외부 변경 충돌 확인, 이력과 복원 연결.
3. 첫 실행을 폴더 선택 → AI 연결 → 첫 파일 작업 순서로 정리.
4. 검증된 범위부터 여러 파일·형식으로 확대.

기존 인증·동기화·캔버스를 유지하면서 주 작업 흐름을 옮긴다. 현재 구조와 사용법은 [데스크톱 안내](../apps/desktop/README.md)를 참고한다.
