# Phase 7 — RAG 구현 계획

- 기존 PostgreSQL 17/Alpine 데이터 볼륨을 보존하며 pgvector 확장이 있는 이미지를 만든다. 적용 전 DB 백업을 남긴다.
- 정규화된 문서 전체를 블록/페이지/문단 내 위치를 보존한 chunk로 분할한다. DB outbox와 Celery 배치 작업으로 임베딩하며 실패·중단·재시도·모델 변경을 처리한다.
- workspace scope를 SQL에서 적용해 pgvector cosine 검색한다. 현재 버전을 기본으로 하며 과거 버전 포함·기준일 검색을 제공한다. 임베딩 장애 시 텍스트 검색 경로와 불완전한 색인 상태를 명시한다.
- workspace 공유 ChatSession/ChatMessage, 요청 중복 방지, 비동기 답변과 기록 복원, VIEWER 채팅을 구현한다.
- 검색 근거만 AIService로 전송한다. 모든 답변 항목은 실제 검색한 chunk 인용을 가져야 하며 근거 없으면 답을 만들지 않는다. 문서·버전·페이지·발췌문으로 출처를 열람한다.
- 캔버스에 AI 채팅 진입점을 추가하고 데스크톱/모바일 화면과 기존 기능 회귀를 검증한다.
- 실제 Gateway 연결은 합성 문장으로 검증하며 사용자 문서를 테스트 데이터로 새로 생성하지 않는다. 기존 READY 문서는 정상 서비스의 자동 색인 대상으로 처리한다.
