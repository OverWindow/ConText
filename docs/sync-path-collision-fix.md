# 동기화 시 경로 UNIQUE 충돌 수정 — 2026-10-27

## 원인

`UNIQUE constraint failed: entries.workspace_id, entries.relative_path`는 서버의 삭제 이력과 같은 경로에 새 UUID로 생성한 파일을 데스크톱의 SQLite 표시용 테이블에 함께 반영할 때 발생했다. 서버는 삭제된 항목과 새 항목을 함께 보존하지만, SQLite의 경로 제약은 삭제/부재 행에도 적용된다. 사용자 저장소와 로컬 서버의 경로 메타데이터를 읽기 전용으로 비교해 실제로 이 조합이 존재하는 것을 확인했다.

## 수정

- 실제 파일 경로를 차지할 항목을 먼저 결정한다. 충돌하는 삭제 이력이나 아직 파일에 적용하지 않은 항목은 SQLite 내부의 별도 경로 슬롯에 보존한다.
- 내부 슬롯에 보관해도 원래 파일 이름·부모 경로·UUID·버전·원본 BLOB·동기화 매핑을 유지한다. 슬롯을 디스크에 만들지 않으며, 유일성 제약을 제거하거나 행을 무시하지 않는다.
- 이름 교환이나 이름 변경 직후 같은 경로에 새 파일이 오는 경우에는 모든 변경 슬롯을 먼저 비운 뒤 한 트랜잭션으로 반영한다.
- 같은 이름으로 다시 만든 폴더가 삭제된 폴더의 메모를 이어받지 않도록 캔버스 식별자와 경로도 분리한다.
- 파일이 기기에 남아 있고 받은 내용과 다르면 기존 보호 동작으로 적용을 보류한다. 원본을 덮어쓰지 않는다.

실제 사용자 DB·원본·서버 데이터는 변경하거나 초기화하지 않았다. DB 버전 10과 기존 제약을 유지하므로 별도 마이그레이션이나 폴더 재연결이 필요 없다.
